Session 25: The breve as tied semibreves

Why. In repeat mode the semibreve and the breve both engrave as 4 heads (cnb:build-duration-stencil, cnb/stencils.ly), so the two cannot be told apart. Doubling to 8 heads for the breve strings too many heads together. The Configurator's operator prefers a breve written as tied semibreves (Configurator session 42), and chose (Configurator session 44, 2026-11-10) to keep the breve as one note whose stencil is the composite, not to split the music into real tied notes. Dots, spacing, the per-pitch repeat field and the duration category the procedure gets all stay as they are. Configurator session 44 draws the same composite in its preview, and its engine round trip waits on this session.

This deliberately changes what a breve engraves in repeat mode, so the goldens and harvests that contain one change.

  2. The composite. In repeat mode (the config's repeat is not #f), a note of duration log L ≤ −1 (breve −1, longa −2, maxima −3) engraves as 2^(−L) of today's semibreve stencils (the 4-copy whole-note stencil), left to right, 1 staff space apart. Each gap holds (make-tie-stencil (cons x1 0) (cons x2 0) 0.12 DOWN), from the left group's right edge x1 to the right group's left edge x2, at the head's centre line, bowing down, with LilyPond's default height limit (1.0) and ratio (0.33). The procedure still gets duration category 0 for all three. The stencil cache keeps the longa and the maxima apart from the breve. With repeat #f nothing changes, and whole notes and shorter values are unchanged.

  4. A README line beside the repeat counts, and a CHANGELOG line. Write docs/session-sets/025-breve-tied-semibreves/configurator-handoff.md, in the form of the earlier handoffs. It gives the composite's measured geometry for the default Configurator notehead at 4 semitones per staff space: each group's width, the gap, the tie's end points, its bow height and thickness, and the whole stencil's X and Y extents.
